## 6. Recommendations for Dataset Quality Improvement

1. **Fix timestamp generation/validation (C1 — 49% of records).** Arrival before departure
   must be rejected upstream. Add a `DURATION_VALID` validation rule (`arrival_time_utc > departure_time_utc`)
   to the sync pipeline (the pipeline already has a `Validation: timestamp` stage that currently
   catches nothing — wire it to this rule).
2. **Derive `country_code` from origin/destination regions (C2/C3 — ~47%).** Either compute
   `country_code` from `origin_region`/`destination_region`, or validate that it matches at least
   one endpoint. Enforce `region ∈ (US states ∪ CA provinces)` **and** country consistency in the
   `origin_region`/`destination_region` validators.
3. **Make `is_delayed` consistent with `status` (C4 — 26%).** Replace the boolean with a derived
   value (`is_delayed := status == 'DELAYED'`) or add a cross-field validation rule.
4. **Reduce timestamp collisions (C5/C6).** If these are intentional (coarse sampling), document the
   precision; otherwise add uniqueness/rounding checks for `departure/arrival_time_utc`.
5. **Fix `border_crossing` flag (C7).** It should equal `(country(origin) != country(dest))`.
6. **Add GPS telemetry.** For the "GPS trajectory" use-case the dataset should expose `latitude`,
   `longitude`, `vehicle_speed_kmh` and per-point `timestamp` so the coordinate-range and speed
   checks (C15/C16) can actually be executed; currently those columns are missing entirely.
7. **Publish versioned metadata** (schema, generation rules, known caveats) in the dataset README so
   consumers can distinguish genuine anomalies from intentional synthetic values.
